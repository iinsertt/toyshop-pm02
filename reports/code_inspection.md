## Нарушение №1. Неинформативное имя переменной

| Параметр | Значение |
|----------|----------|
| **Файл** | `src/Module1_Catalog/catalog.py` |
| **Строка** | 80 (метод `search_by_name`) |
| **Нарушение** | Переменная названа одной буквой: `n = query.strip().lower()` |
| **Почему это плохо** | Однобуквенные имена не передают смысл, ухудшают читаемость и сопровождение кода. По PEP 8 имена должны быть осмысленными. |
| **Как исправлено** | Переменная переименована в `normalized` — отражает, что строка приведена к нормальному (нижнему) регистру. |
| **Влияние на качество** | Код стал самодокументируемым: назначение переменной понятно без анализа контекста. |
| **Коммит** | `4170a9b` |

## Нарушение №2. Строка длиннее 120 символов

| Параметр | Значение |
|----------|----------|
| **Файл** | `src/Module1_Catalog/catalog.py` |
| **Строка** | 81 (комментарий в `search_by_name`) |
| **Нарушение** | Однострочный комментарий длиной более 120 символов. |
| **Почему это плохо** | Длинные строки требуют горизонтальной прокрутки, не помещаются при сравнении версий и на узких экранах. PEP 8 рекомендует ограничивать длину строки. |
| **Как исправлено** | Комментарий разбит на две короткие строки. |
| **Влияние на качество** | Код читается без прокрутки, удобнее просматривать diff. |
| **Коммит** | `49c3753` |

## Нарушение №3. Отсутствие docstring у публичного метода

| Параметр | Значение |
|----------|----------|
| **Файл** | `src/Module1_Catalog/catalog.py` |
| **Строка** | 69 (метод `get_all`) |
| **Нарушение** | У публичного метода `get_all` отсутствовала строка документации (docstring). |
| **Почему это плохо** | Без docstring непонятно назначение метода; IDE не показывает подсказку. PEP 257 требует документировать публичные методы. |
| **Как исправлено** | Добавлен docstring: «Вернуть все загруженные товары.» |
| **Влияние на качество** | Появилась документация и всплывающие подсказки в IDE, единообразие с остальными методами. |
| **Коммит** | `57a0a79` |

## Нарушение №4. «Магическое число» в коде

| Параметр | Значение |
|----------|----------|
| **Файл** | `src/main.py` |
| **Строка** | 99 (функция `catalog_menu`, фильтр по цене) |
| **Нарушение** | В вызов `ask_int("Максимальная цена: ", 1000000)` зашито «магическое число» `1000000`. |
| **Почему это плохо** | Назначение числа неочевидно, при изменении значения пришлось бы искать его по всему коду. |
| **Как исправлено** | Число вынесено в именованную константу `MAX_PRICE_DEFAULT = 1_000_000` с комментарием. |
| **Влияние на качество** | Смысл значения ясен из имени, значение меняется в одном месте. |
| **Коммит** | `daac6dc` |

## Нарушение №5. Дублирование кода

| Параметр | Значение |
|----------|----------|
| **Файл** | `src/Module3_Order/order.py` |
| **Строки** | 125 (`get_order`) и 166 (`list_orders`) |
| **Нарушение** | Длинный список столбцов SQL `order_number, surname, ...` повторялся в двух запросах. |
| **Почему это плохо** | Дублирование нарушает принцип DRY: при изменении схемы нужно править несколько мест, легко ошибиться и рассинхронизировать запросы. |
| **Как исправлено** | Список вынесен в константу `ORDER_COLUMNS`, запросы используют f-строку `f"SELECT {ORDER_COLUMNS} FROM orders ..."`. |
| **Влияние на качество** | Единый источник истины для набора столбцов, меньше риск ошибок при изменении схемы. |
| **Коммит** | `4d597e5` |
